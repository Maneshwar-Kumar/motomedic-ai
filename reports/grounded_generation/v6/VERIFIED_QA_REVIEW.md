# Open manual draft/verify software review, version 6

The composer completes a private draft, finalizes all selected source-owned displays and verified service metadata, and asks a separate provider call to evaluate the exact complete response. Ordinary decisions are RELEASE_COMPLETE, RELEASE_PARTIAL and SHOW_FALLBACK. Clarifications and safety stops have separate release decisions. A partial response already contains its limitations before verification. The verifier never supplies replacement answer text.

Sixteen fake-provider boundary tests pass against the real immutable source authority and index. They cover complete and partial release, exact fallback/system wording, unrelated rejected drafts, one correction and re-verification, malformed or inconsistent verdicts, provider quota errors, required warning inclusion before verification, source/history changes, safety precedence, and response/session/operation mutations at presentation. The JSON report records exact code, policy, schema and integration hashes before and after the final run. No source-authority or frozen version 5 objects were edited for version 6.

Successful text remains an internal buffer. The root-owned API binds the operation, durably commits the view, then delivery streams the same committed text. Ordinary questions and procedures do not require authored question, scope or action selection. The inherited controller still protects selected-manual identity, immutable typed history and known safety predicates. A valid citation or procedure label does not establish semantic support: that is the online evaluator's separate task.

The composer retains private attempts only in internal fields. Public telemetry contains decision enums, hashes, counts, durations and redacted provider telemetry. Failed calls retain actual generation attempt accounting. Cache use is disabled. Original input/output, concurrency, request-byte and worst-case minute reservation limits remain unchanged. A draft can consume enough reservation that its verifier cannot run that minute; this produces SYSTEM_ERROR with no technical buffer, without truncating evidence or silently relaxing limits.

These tests establish software controls, not real-model accuracy, latency, cost, source rights or public release eligibility. The real-provider fresh-question evaluation remains necessary. Semantic verification is probabilistic and an accepted response is not a proof of factual correctness. The review JSON binds the tested implementation and leaves those limitations explicit.
