9  Release check and demo script
Open a new browser in a logged-out session; verify app URL and model/manual version banner
Ask an answerable manual question and inspect exact cited page; follow up “I checked; it was normal” and show different eligible next step
Try “I did that; it still does not work” to prove no false assumption and no looping
Upload a relevant photo; show visible-observation extraction, uncertainty and source lookup
Ask for an undocumented repair; show justified abstention and verified OEM escalation
Simulate retrieval failure; demonstrate SYSTEM_ERROR differs from “not documented”
Show evaluation table and representative trace; demonstrate at least one tracked improvement or deliberate trade-off
10  Known limitations and honest claims
The owner manual supports a provisional source-checked corpus; independent review, variant confirmation and held-out evaluation are still required before performance claims
App logic can fail closed, but semantic sufficiency classifiers and visual interpretations remain probabilistic
If OEM documentation is incomplete, the correct system behavior may be escalation rather than further instructions
A polished hosted demo is necessary, but it does not establish production readiness, field safety or verified repair success
11  Guardrail implementation checklist
G-01  Lock source checksum, manual edition and confirmed bike variant in each session; reject mismatches before retrieval or cached-answer lookup.
G-02  Check extraction completeness for warnings, prerequisites, table headers/units and figure references; send uncertain pages to manual review.
G-03  Require approved StepDefinition/ApplicabilityRule predicates and a complete reviewed dependency manifest, then deterministic and semantic claim checks; source gaps block and enter review.
G-04  Implement TRUE/FALSE/UNKNOWN eligibility, immutable superseding corrections, typed outcomes and no unjustified repetition; prefer explicit OEM order without inventing one.
G-05  Keep SUPPORTED, AMBIGUOUS, UNSUPPORTED, SAFETY_STOP and SYSTEM_ERROR distinct; preserve verified safety-stop precedence; source review is not rider-resolvable.
G-06  Test prompt injection in user text, uploaded images and the manual; none may override source or safety rules.
G-07  Compile approved golden dialogue prefixes and terminal answers into exact-match cache keys containing manual checksum, variant, flow and policy version; fail closed on stale or draft entries.
G-08  Keep raw media out of ordinary logs, store keys server-side, and set file, rate and spend limits before a public demo.
G-09  Add regression cases for wrong variant, missing warning, ambiguous visual, invalid citation, retrieval outage, exhausted paths and cache mismatch; require a review sign-off before release.

Current hosted status and bounded policy
Hosted ingestion and embedding comparisons are complete. The selected BGE M3 index index_a3282c4d98cf54595e4ba168 has 532 search chunks and 277 section parents at a 1,024-token budget. Authenticated Cloud Run Qdrant serves immutable vectors from private Cloud Storage with min zero and max one instance; cold starts restore vectors without reparsing or re-embedding. The recorded backend smoke report passes 11/11 checks. Rider UI, integrated eligibility controller and gated generator remain pending; may_generate_procedural_advice stays false.
Section parents are contextual candidates. Independent review must establish procedure boundaries and approve StepDefinition, ApplicabilityRule and per-step dependency manifests against the original pages. A missing, empty, stale or unapproved dependency set cannot establish sufficiency. PDF page 103 has a flagged whole-page text/image fallback after Docling omission. Confirm year, market, variant, edition, source URL, display/hosting rights and the OEM service route before public advice.
Use dense cosine retrieval plus BM25 and RRF, initial parent/dependency assembly, source and applicability checks, at most one exact-ID recovery for approved missing dependencies, and at most one conditional cross-encoder attempt for uncertain ordering. Reassemble while retaining mandatory evidence. Missing review must not trigger reranking. Conditional is the normal policy; off and always_diagnostic are ablations. Current unreviewed bundles skip reranking and block technical generation.
Provisional retrieval bounds are fused pool 20, five assembled hits, recovery pool 40, rerank pool 20, 100 query/passage pairs and 256 mandatory dependency IDs. More than 256 dependencies yields SYSTEM_ERROR without truncation. Distinct-parent top-three overlap below 0.5 or relative RRF margin at most 0.05 are PROVISIONAL_UNCALIBRATED. Zero BM25 matches provide no agreement signal. Queries beyond the current cross-encoder 128-token bound skip inference with an explicit reason and retain full input. Independently reviewed calibration and held-out evaluation remain required.
Measure warm text p50 <=2.5 seconds and p95 <=5 seconds, photo p95 <=10 seconds, with cold starts separate. TTFO runs from confirmed input to the first releasable answer token; loading indicators do not count and technical tokens remain withheld until validation. Report fast, recovery/rerank and combined p95, fallback frequency, stage failures and cost per correctly handled case.
Exact reviewed paths are keyed by manual checksum, confirmed variant, intent/relevant symptoms, typed outcomes, flow/controller and policy versions, with prompt and approval dependencies. Draft, stale and mismatched entries miss closed. Changes to rules, review, dependencies or policy invalidate affected cache entries and cases. Manual checksum, parser/chunker or embedding changes create a new index version; unchanged document vectors are reused for retrieval-policy changes.

Reconciliation change record 9 October 2026
These changes reconcile earlier planning language with TRD v0.4 and recorded project evidence. They do not claim new runtime functionality or source approval.
Document authority
Previously: Four v0.2 drafts lacked a clear precedence rule.
Now: TRD v0.4 governs design and technical contracts; other documents refreshed to v0.3; manual remains the authority for bike facts.
Build and hosting
Previously: Offline ingestion wording and Streamlit Community Cloud as the provisional host; local NumPy/LSA baseline.
Now: Hosted versioned GitHub ingestion; authenticated Cloud Run Qdrant with private Storage; Streamlit rider UI still pending.
Embeddings and chunking
Previously: Compact embedding baseline; hierarchical chunking without a selected hosted budget.
Now: BGE M3 candidate selected with 1,024-token chunks, 532 search children and 277 section parents; reviewed procedure boundaries still pending.
Reranking
Previously: Generic conditional reranker or local lexical second pass with no explicit scheduling contract.
Now: One exact dependency recovery and one conditional cross-encoder attempt; source review first; distinct-parent triggers provisional; mandatory evidence survives reassembly.
Evidence sufficiency
Previously: Attach prerequisites/warnings and verify claims without an explicit approved dependency manifest.
Now: Required/attached/missing IDs plus manifest version/review; empty or unreviewed set fails closed; page presence alone is insufficient.
Controller authority
Previously: Deterministic state machine described broadly; no approved rule registry or three-valued contract.
Now: Approved StepDefinition and ApplicabilityRule records; TRUE/FALSE/UNKNOWN predicates; eligibility distinct from evidence and final validation.
Clarification and failure routing
Previously: Partial evidence could clarify; answer/clarify/abstain aliases and unsafe/unsupported merged in the diagram.
Now: Five canonical statuses; safety-stop precedence; rider questions only for resolvable facts; source gaps block; outages stay SYSTEM_ERROR.
Corrections and release priorities
Previously: Correction/backtracking P1; caching and tracing positioned as enhancements.
Now: Corrections P0 under immutable attempts; basic tracing/cache rejection required before release; optional voice and expanded cache coverage remain P1.
Caching and versioning

Evaluation and latency

Spending
