# Private question interface wiring

The rider submits a question or asks another question. The UI sends the original text to the hosted backend; it does not choose a symptom route or send a benchmark record ID. The original initial-30 endpoint remains a compatibility/evaluation interface only.

## Serving path

Private Cloud Run UI → fresh audience-bound managed identity token + signed visitor capability → durable admission → hybrid retrieval over the selected immutable index → conservative reviewed question-scope admission → existing eligibility/dependency/warning/citation gates → exact reviewed Arm A answer → atomic operation/session commit → verified complete-unit SSE → browser display.

Arm A makes zero answer-provider calls. It accepts arbitrary input but can answer only admitted reviewed propositions. The current scope gate preserves word order, negation, comparison symbols and additional clauses; it accepts bound canonical questions and six independently source-checked E20/mirror paraphrases. Other wording can abstain even when the manual contains relevant information. This wiring does not establish general semantic interpretation, unrestricted manual coverage or matched end-to-end accuracy.

Optional exact source-authored clarification and issued typed feedback remain available. Ordinary questions continue in the same session independently of that feedback. No source excerpt, PDF page image or crop is delivered; citations contain immutable IDs and page metadata. Photos remain disabled.

## Identity, persistence and limits

Both services require Cloud Run IAM. The UI uses `motomedic-rider-ui` and its service-scoped backend invoker grant. Only the UI and backend accounts can access the shared visitor signing secret. Secret values are never recorded in reports. The verified private browser principal determines a stable keyed visitor nonce, so refreshing or starting a new conversation does not reset visitor usage. Anonymous public access requires a separate reviewed identity/admission design.

Session snapshots, operations and usage counters use MotoMedic-specific Firestore groups. Their `expires_at` TTL policies are enabled. Fixed session lifetime is 24 hours; idle expiry is 30 minutes and never extends the lifetime. Expired records are denied by application checks while physical Firestore deletion may occur later. Generic `versions` TTL remains disabled; the current writer uses `arm_a_session_versions`.

Admission enforces 20 accepted turns per session, six requests per visitor per minute, 30 per visitor per rolling 24 hours, and shared limits of 60/minute and 250/24 hours. Conflict/known terminal errors never automatically resubmit a mutation. Uncertain transport/commit outcomes retain an operation key for read-only recovery. Completed operations can replay during their lifetime even after idle session expiry.

## Build, review and rollback

The frozen backend context is `build/arm-a-ui-wiring-v2`; the separate UI context is `build/rider-ui-wiring-v2`. Backend overlays the prior immutable model/index image, without ingestion, embedding or new model downloads. UI software fixtures exist only in its test stage. Both final runtimes use non-root users. Deploy only successful immutable image digests with `tools/connect_arm_a_ui.py` after its budget/guard and independent-context checks.

Evidence lives under `reports/arm_a/ui_wiring_v1/`: implementation/context reviews, exact preparation bindings, hosted build results, service/IAM receipts and live acceptance reports. Local verification passed 90 backend/source checks and 44 UI checks; hosted counts are recorded independently. A single acceptance run does not establish p95 latency, photo performance or public release readiness.

Run private API acceptance with `tools/accept_arm_a_ui.py`, using a TLS-capable Python runtime. Run the browser path with `--browser` and Playwright. Credentials remain in memory. The harness records routes, hashes, page metadata and timing; it never logs bearer tokens or visitor secrets.

Rollback the UI to its prior verified revision or disable its connection. The backend predecessor is `motomedic-arm-a-00002-jh2`; routing traffic back there disables the newly installed question API. Preserve the managed session records and immutable review/index bindings. Never re-enable billing after the budget guard has stopped it without owner authorization.

Backend revision `motomedic-arm-a-00003-gs2` and UI revision `motomedic-rider-ui-00001-wg9` passed hosted builds (117 backend/source/client checks; 44 UI checks) and private real-retrieval/API/browser acceptance. These single-case observations are not p95 or a proven cold/warm classification.

The hosted UI is `https://motomedic-rider-ui-5uyul6ay6a-uc.a.run.app` and requires IAM. An authenticated localhost proxy can forward a browser to it: `gcloud run services proxy motomedic-rider-ui --project=motomedic-ai-20261009 --region=us-central1 --port=8787`. This is forwarding only; application/model execution remains hosted. Anonymous access is disabled.

Additional live checks passed: a different signed visitor received 404 for both saved-session and saved-operation access; the exact reviewed EXP003 path clarified the switch observation, issued its supported page31 action, and abstained after unresolved feedback without repetition or a newly inferred normal observation. This is bounded exact-path coverage, not full adaptive release. The final independent receipt audit closes every named private deployment condition.
